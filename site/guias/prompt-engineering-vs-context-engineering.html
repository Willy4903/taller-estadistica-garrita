Prompt engineering vs context engineering

Respuesta en 20 segundos

Prompt engineering responde a '¿cómo formulo la instrucción?'. Context engineering responde a '¿qué información, herramientas y reglas necesita la IA para resolver correctamente el problema?'. El segundo incluye al primero y es lo que permite pasar de consultas sueltas a sistemas de trabajo.

Prompt engineering

Es el diseño de instrucciones: estructura, descomposición, ejemplos, criterios, restricciones, formatos, evaluación e iteración. Mejora el resultado sin cambiar de modelo.

Context engineering

Es el diseño de todo lo que el modelo recibe: system prompt, instrucciones, archivos, datos, memoria, herramientas, historial y reglas. Un buen modelo con mal contexto puede producir un mal resultado; un contexto bien construido puede transformar la calidad del trabajo.

Un caso práctico

Para un informe mensual de ventas, el prompt dice 'compara 2025 y 2026'. El contexto añade el rol de analista, el archivo con los datos, la política de redondeo, un informe aprobado como ejemplo, la decisión de excluir devoluciones tomada el mes anterior y una calculadora para comprobar variaciones.

Cuándo usar cada uno

Para tareas puntuales basta un buen prompt. Cuando la tarea se repite, depende de documentos o requiere herramientas, conviene diseñar el contexto: un Project, un asistente configurado, un workflow o un agente.

Preguntas frecuentes

¿El context engineering reemplaza al prompt engineering?

No: lo contiene. Seguir escribiendo buenas instrucciones es parte de construir buen contexto.
